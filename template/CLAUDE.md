# Pilot project repository

This is a pilot project repository of KISENO. Besides its own goal, the project feeds one or more AI service blueprints: `casebook.yaml` names them, with the case slug and the slugs of the research question pages per blueprint. Read it at the start of every session; while it says `kickoff: open` or `kickoff: started`, offer the kick-off interview (skill `kickoff-interview`, plugin kisz-code). If the skill `kickoff-interview` is not available, tell the engineer to install or update the plugin kisz-code from the kisz marketplace, and do not fill `casebook.yaml` by guesswork.

Insights for a blueprint (a design decision, an abandoned approach, an evaluation result, an interview) go into the engineer's local clone of `blueprint-<slug>/casebook/` through the commands `/kisz-code:casebook decision`, `/kisz-code:casebook deadend`, `/kisz-code:casebook scan` and `/kisz-code:casebook closing` or, for the first writes at the kick-off, the `kickoff-interview` skill, never by hand and never without the engineer's confirmation. The `do_not_publish` list in `casebook.yaml` binds every casebook entry. Every casebook entry passes the check `casebook.py redact` of the plugin kisz-code before it is shown for confirmation; the check reads two local list files, `.claude/casebook-terms.txt` and `.claude/casebook-documents.txt`, which are never committed. Partner persons, contact data and partner document text never reach a casebook.

Skills from the kisz marketplace: `casebook-entry`, `casebook-scan` and `closing-interview` (plugin kisz-code), `kisz-context` for the project page, `kisz-writing` for prose, `sbatch` and the `cluster-run` agent for the HPI cluster. Project setup, tests, lint and formatting are described in `development.md`.
